## 2. 产品目标（可衡量）

**总目标：把质量人做一次「全流程过程能力分析 + 报表」的耗时从小时级降到分钟级，且统计结果可直接用于产线决策。**

| # | 目标 | 可衡量指标（验收口径） |
|---|---|---|
| G1 | 消灭 Excel 手改公式 | 用户从「拿到一份 xlsx」到「看到 Cpk + 控制图 + 柏拉图的完整分析」全程 ≤ 5 分钟，且全程 0 次手动编辑公式。基准：旧工具/Excel 流程 ≥ 40 分钟 |
| G2 | 统计正确性做到可信 | 组内/整体标准差口径分离，Cp/Cpk（组内）与 Pp/Ppk（整体）在示例数据上与 Minitab 结果误差 ≤ 0.001；判异准则命中与参考实现一致 |
| G3 | 数据主权可控 | 离线模式下，除用户主动发起的 AI 请求外，**0 字节**数据离开本机（可用浏览器 Network 面板验证：无任何外部请求） |
| G4 | 结果「说人话」 | AI 版对控制图异常的解读必须落到「哪台设备/哪个子组/哪个特性有问题 + 一条可执行动作」，而非复述统计名词 |
| G5 | 旧数据平滑迁移 | 旧版 Python 工具导出的 xlsx（dimension/defect 双 sheet）可直接导入，无需人工改列名，导入成功率 100% |

## 3. 用户画像与核心场景

### 3.1 用户画像

- **主用户**：制造业质量从业者（IQC/IPQC/OQE/PE），懂 CPK/SPC 术语，日常在 MES 与 Excel 间搬数据。
- **次级用户**：质量主管（要报表、要看趋势）、内审/客户审核对接人（要资料、要可追溯）。
- **环境约束**：工厂电脑可能无外网、无 IT 基建权限；军工/重工场景对「生产数据上云」高度敏感。

### 3.2 核心场景

- **S1 IQC 来料快速判定**：供应商送一批外壳，QC 拿到 50 条测量数据，需要在 5 分钟内算出 Cpk 并判定是否放行，同时出一张柏拉图说明主要缺陷类型。
- **S2 制程异常排查**：产线发现某特性连续超差，工程师把近 5 个班次数据导入，用 Xbar-R + 判异准则定位是「哪一批/哪个子组」漂移，判断是设备还是材料问题。
- **S3 客诉 8D 前的原因定位**：客户投诉某尺寸不稳定，需在 8D 启动前用 I-MR + 直方图 + 正态性检验确认数据是否稳定、是否服从正态，为后续 8D 提供数据支撑。
- **S4 内审/客户审核准备**：审核前临时要 SPC 报表，用「一键日报导出」5 分钟产出 Excel + PDF（含控制图、CPK 汇总、柏拉图）。

## 4. 统计口径定义（正确性底线，工程师必须严格按此实现）

### 4.1 标准差双口径

- **子组划分【已确认】**：按「物料（特性）」分组后划分子组，默认子组容量 **n=5**（可配置），并提供三种划分模式：
  1. **固定容量自动划分**：按 n 连续切分（默认模式）
  2. **按列自动划分**：按指定列（如 批次/时间/班次）分组，每组为一个子组
  3. **手动指定**：用户在数据表上手动圈选子组边界
  - 子组内为同一时刻/同一批次的连续样本。子组容量 n 须为整数且 ≥2，否则报错。
- **组内标准差 σ_within（用于 Cp/Cpk）**：
  - 由子组内极差的平均 `R̄` 或子组内标准差的平均 `S̄` 估计：`σ_within = R̄/d2`（n≤10 用 R 法）或 `σ_within = S̄/c4`（n>10 用 S 法）。
  - 若数据无子组结构（每条只 1 个值），**禁止**用 ddof=0 冒充组内，必须提示用户「数据不支持组内标准差，Cp/Cpk 不可计算」或降级为 I-MR 单值移动极差估计 `σ_within = MR̄/d2`（d2 取 n=2 的值 =1.128）。
- **整体标准差 σ_overall（用于 Pp/Ppk）**：全部测量值（同特性）的样本标准差，`ddof=1`。
- **修正旧工具缺陷**：旧工具 std 用整体 ddof=1 且未分子组，导致 Pp==Cp。新版必须让 Cp/Cpk 用 σ_within、Pp/Ppk 用 σ_overall，二者通常不相等。

### 4.2 能力指数公式（双侧规格）

```
Ca   = (均值 - 规格中心) / (USL-LSL)/2           # 准确度，可正可负
Cp   = (USL - LSL) / (6 * σ_within)
Cpk  = min( (USL - 均值)/(3*σ_within), (均值 - LSL)/(3*σ_within) )
Pp   = (USL - LSL) / (6 * σ_overall)
Ppk  = min( (USL - 均值)/(3*σ_overall), (均值 - LSL)/(3*σ_overall) )
```

- **单侧规格**：仅给 USL 或 LSL 时，Cp/Pp 无定义（显示 N/A），只算 Cpk/Ppk。
- **西格玛水平【已确认】**：**两个口径必须同时显示并明确标注差异**，避免用户误解：
  - 短期/组内口径：`Sigma_level = 3 * Cpk`
  - 工程口径（含 1.5σ 漂移）：`Sigma_level_bench = 3 * Cpk + 1.5`
  - UI 要求：两项并排展示，分别加标签「短期能力(3×Cpk)」与「工程口径(含1.5σ漂移)」，并附一行说明文案：「两者相差 1.5σ，用于不同场景，请勿混用」。Cpk 由 σ_within 计算。
- **PPM 预估（期望不良率）**：用 σ_overall 与规格限，按正态分布双侧尾部面积换算 PPM；同时给出基于 σ_within 的「潜在 PPM」用于对比。**非正态数据必须走非正态估算分支**（见 4.4），并在 UI 标注「基于正态假设，非正态时仅供参考」。

### 4.3 控制图与控制限常数

- **计量型**：
  - `Xbar-R`：CL=X̄，UCL/LCL=X̄±A2·R̄；R 图 CL=R̄，UCL=D4·R̄，LCL=D3·R̄
  - `Xbar-S`：CL=X̄，UCL/LCL=X̄±A3·S̄；S 图 CL=S̄，UCL=B4·S̄，LCL=B3·S̄
  - `I-MR`：I 图 CL=X̄，UCL/LCL=X̄±E2·MR̄（E2=2.66 对应 n=2）；MR 图 CL=MR̄，UCL=D4·MR̄，LCL=D3·MR̄
- **计数型**：
  - `P` 图：CL=p̄，控制限=p̄±3·√(p̄(1-p̄)/n_i)（n_i 不等时为变限，逐点计算）
  - `NP` 图：CL=np̄，控制限=np̄±3·√(np̄(1-p̄))（n 恒定）
  - `C` 图：CL=c̄，控制限=c̄±3·√c̄
  - `U` 图：CL=ū，控制限=ū±3·√(ū/n_i)
- **常数表**：A2/A3/D3/D4/B3/B4/d2/E2/c4 按子组容量 n 自动查表（提供 n=2..25 的常数表）。**n 超出 2..25 范围时必须报错提示，不允许外插**。D3、B3 在 n＜7（D3）等情形下取 0（LCL 不存在，UI 显示为不画下控制限）。
- **常数表自检（主理人硬约束，QA 独立验证前提）**：内置常数表的每一项取值必须与公认标准表（AIAG SPC 手册 / ASTM E2587）**逐项比对一致**；提供可被 QA 独立运行的「常数表自检」用例（对 n=2..25 全覆盖比对）。当 n 超出 2..25 时，系统必须报错终止计算，**不得外插**。这是 QA 能否独立验证控制图正确性的前提。

### 4.4 直方图与正态性

- 直方图叠加 USL/LSL 规格线 + 目标线；分箱数默认 `Sturges` 规则，可在配置中改。
- 正态性检验：默认 **Anderson-Darling**，同时给 **Shapiro-Wilk**（n≤50 时优先显示 S-W）。输出统计量与 p 值。
- 判定：p ≥ 0.05 → 不拒绝正态；p < 0.05 → 非正态，UI 提示「数据非正态，Cpk/PPM 基于正态假设，建议参考非正态能力分析（Box-Cox / 非参数）」，本期只给说明与告警，不做变换拟合（列入 P2）。

### 4.5 数据预处理

- **空值**：自动剔除，剔除条数在结果页显著提示。
- **异常值**：识别（默认 Grubbs 或 箱线图 1.5IQR，可切换），**只标注不自动删**，必须在 UI 上人工勾选确认后方可排除，并记录到分析配置（可追溯）。
- **子组划分**：支持「按固定容量自动分」「按指定列（如 批次/时间）分」「手动指定」三种。

## 6. 双模式行为规格

### 6.1 模式判定逻辑

1. 启动时读取本地设置中的 `aiConfig`（Base URL / API Key）。
2. 若未配置 Key → **离线模式**。
3. 若已配置 → 发一次轻量连通性探测（如 `GET {baseUrl}/models` 或最小 chat 请求，超时 3s）。
   - 成功 → **AI 模式**
   - 失败/超时 → **离线模式**，且保留配置、在设置页提示「AI 服务暂不可用，已降级为离线模式」，并给「重试」按钮。
4. 运行中可随时在设置页切换/重测，无需刷新。

### 6.2 离线模式下 UI 的具体降级表现

- 顶部状态徽标显示「离线模式」（灰）；AI 助手入口**置灰不可点击**，hover 提示「配置 AI 服务后可用」。
- 所有统计分析、控制图、柏拉图、报表导出、项目库、JSON 导入导出**全部可用**，无任何功能因离线被砍。
- 所有 AI 相关的按钮（如「AI 解读」「AI 生成报告文字」「AI 建议」）隐藏或禁用，不出现空白面板。
- 数据全程只在 IndexedDB/OPFS 内，不发任何网络请求。
- 设置页保留 AI 配置表单，供用户随时填入 Key 后升级为 AI 模式。

### 6.3 AI 版各功能输入/输出

| 功能 | 输入 | 输出 | 约束 |
|---|---|---|---|
| 控制图异常解读 | 当前特性名、控制图类型、违规明细（规则号+位置）、能力指数摘要 | 中文诊断：「问题在子组 #k / 特性 X，疑似设备漂移/材料波动，建议动作：…」 | 必须落到具体子组/特性+可执行动作，禁止只复述统计名词 |
| 能力分析解读 | 双口径标准差、Cp/Cpk/Pp/Ppk、Ca、PPM、正态性结果 | 中文结论：过程是否受控/是否满足 1.33/1.67 门槛、主要问题在准确度还是精密度 | — |
| 改善建议 | 上述任一分析结果 | 3 条以内、按优先级排序的改善动作 | 需标注依据的分析点 |
| 报告文字生成 | 分析结果 + 用户可选填的备注 | 可直接粘贴的 Markdown 报告段落（摘要/结论/建议） | — |
| 数据问答 | 用户自然语言问题 + 当前项目数据结构摘要 | 回答 | 不把原始明细全量上传，仅上传统计摘要（保护数据主权） |

> **AI 隐私规则【已确认】**：默认只发送统计摘要（均值、标准差、指数、违规列表），**不发送逐条原始测量值**；若用户需要 AI 基于明细分析，须显式勾选「允许发送原始数据」并二次确认后方可发送。此方案按 v1.0 原稿执行，用户已拍板确认。

## 7. UI 设计稿（文字描述）

### 7.1 主布局

- **左侧导航栏**（固定宽 ~220px，可折叠）：项目切换器 + 菜单项【数据导入 / 能力分析 / 控制图 / 柏拉图 / 报表导出 / AI 助手 / 设置】。

- **主内容区**：随导航切换，采用「配置面板（左/上）+ 图表结果（右/下）」的双区结构。

### 7.2 各核心页面

- **数据导入页**：拖拽区（xlsx/csv）+「粘贴 CSV」标签页；导入后展示 sheet/列映射预览表，允许手动改列映射；校验结果区显示「识别到特性数 / 测量记录数 / defect 类型数 / 剔除空值数」。旧格式自动识别 dimension/defect。
- **能力分析页**：顶部特性选择器；中部配置卡（子组容量、子组划分方式、异常值处理、单/双侧规格）；结果区表格化输出全部指数（含双口径标准差与 PPM），并配直方图+规格线、正态性检验结论卡。
- **控制图页**：图表类型选择（Xbar-R/Xbar-S/I-MR/P/NP/C/U）+ 判异准则开关面板（西方电气 4 / 尼尔森 8，逐条复选）；主图为 ECharts 控制图（控制限虚线、中心线、违规点高亮）；下方违规明细表（规则号/位置/涉及点，点击定位到图上）。
- **柏拉图页**：交互式柱状+累计折线双 Y 轴，80% 分界线；悬浮 tooltip 显示频数与累计占比；支持按频数降序排列与「其他」合并阈值。
- **报表导出页**：导出项勾选（CPK汇总/不良统计/原始尺寸/原始不良/控制图截图/柏拉图截图）；预览当前日报；「导出 Excel」「导出 PDF/打印」按钮；P1 支持模板保存。
- **AI 助手页**（离线时置灰）：对话式面板；快捷指令按钮「解读当前控制图」「解读能力分析」「生成报告文字」；每条回复可「插入到报告」；明确标注本次请求发送了哪些数据（摘要/明细）。
- **设置页**：AI 配置（Base URL / API Key / 模型名 / 连通性测试 / 是否允许发送原始数据）；判异准则默认开关；控制限常数表展示；数据与隐私说明；项目库管理入口。

### 7.3 关键交互

- 切换特性/时间范围即时重算并重绘（前端内核，无网络往返）。
- 违规点点击 → 图上定位 + 侧栏展开该子组明细。
- 所有「删除数据」类操作（异常值排除等）均为「标注→确认」两步，且可撤销。

## 8. 数据模型

关系：**项目 1—N 数据集 1—N 特性(物料) 1—N 测量记录**；**特性 1—N 子组**；**特性 1—1 规格限**；**项目 1—N 分析配置**；**数据集 1—N 不良记录**。

```
Project
  id, name, description, createdAt, updatedAt, schemaVersion
  datasets: Dataset[]
  analysisConfigs: AnalysisConfig[]
  aiUsageLogs: AiUsageLog[]        # 记录每次 AI 请求发送了什么（审计/隐私）

Dataset
  id, projectId, name, sourceType('xlsx'|'csv'|'json'), importedAt
  rawFileName
  characteristics: Characteristic[]   # 由 dimension sheet 按「物料名称」聚合而来
  defectRecords: DefectRecord[]       # 由 defect sheet 而来

Characteristic (特性/物料)
  id, datasetId, name(原「物料名称」)
  specLimits: SpecLimits              # 1—1
  measurements: Measurement[]         # 1—N
  subgroups: Subgroup[]               # 1—N（按子组划分方式生成）
  nullCount(剔除空值数), outlierFlags[]
  preprocessConfigRef

SpecLimits
  usl: number|null, lsl: number|null, target: number|null, unit: string

Measurement
  id, characteristicId, value:number, subgroupId, timestamp?/batch?, excluded:boolean, excludeReason?

Subgroup
  id, characteristicId, index, size, measurementIds[], mean, range, std

DefectRecord
  id, datasetId, defectType, count, category?

AnalysisConfig
  id, projectId, name
  subgroupCapacity(default 5), subgroupMode('fixed'|'byColumn'|'manual')
  sigmaMode ('R'|'S'), outlierMethod('grubbs'|'iqr'), outlierConfirmedIds[]
  weRules: {r1..r4: boolean}, nelsonRules: {r1..r8: boolean}

AiUsageLog
  id, projectId, feature('chartExplain'|'capExplain'|'suggest'|'report'|'qa'),
  sentPayloadScope('summary'|'raw'), model, requestedAt, ok
```

**持久化**：项目元数据与分析配置存 IndexedDB；大批量测量记录存 OPFS（结构化文件）；导出项目包为单 JSON（含全部上述实体 + schemaVersion，便于版本迁移）。
