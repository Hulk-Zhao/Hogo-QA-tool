# AI 接入与排障

> 由 README 外迁而来。README 只保留结论（AI 是可选能力、key 只存本机浏览器），
> 接入步骤、报错对照表与交互行为说明放在这里。

## AI 助手返回空 / 连不上本机模型怎么办

AI 模式对接本机 Ollama / LM Studio 等 OpenAI 兼容服务。以下三类问题最常见，可自助排查。

**1）返回内容为空**

本机 Ollama 的**推理模型**（`qwen3.5`、`deepseek-r1` 等）会先生成长篇「思考」，
而思考过程与正文**共享同一份输出配额**：配额被思考吃光时，正文即为空
（服务端返回 `finish_reason: length`，`content` 为 0 字符）。本工具**默认已开启
「关闭模型思考」**（请求带 `reasoning_effort: none`），请到「设置」页确认该开关为开启。

> ⚠️ 若你手动关掉了「关闭模型思考」，请到同页调大「最大输出 tokens」。
> 但要注意：**推理模型的思考长度不可预测**。实测 `qwen3.5:9b` 在本工具的摘要任务上，
> 即使把上下文放宽到 16384、配额给到 4096，思考过程仍会耗尽全部配额、`content` 依旧是空的。
> 因此**除非确有必要，建议保持「关闭模型思考」为开启状态**（本工具默认即开启）。

**2）双击版连不上本机 Ollama**

`file://` 打开时页面 origin 为 `null`，而 Ollama 默认对 `Origin: null`
返回 **403 且不带 CORS 响应头**，浏览器跨源策略因此拦截请求。二选一解决：
设环境变量 `OLLAMA_ORIGINS=*` 后重启 Ollama；或改用 `start.bat` 通过本地服务打开。

**3）提示上下文不足 / 请求被截断**

Ollama 默认上下文窗口 `num_ctx = 4096`，而本工具发送的统计摘要 JSON 本身已约
**2,100 tokens**，余量偏薄。设 `OLLAMA_CONTEXT_LENGTH=16384` 放宽。

**4）提示「请求内容被服务端拒绝，请检查模型名与参数。（HTTP 400）」**

该提示的括号里现在会带上**服务端返回的原文**（气泡下方另有独立的一行「服务端原文」），
例如 `（HTTP 400：model is required）`。请以服务端原文为准排查，常见两种：

- `model is required`：**「设置」页的「模型名」是空的**。本工具已在探测阶段就拦住这种情况
  （模型名为空时直接判定离线模式并在「设置」页说明），不会再发出必然 400 的请求。
- `model 'xxx' not found`：模型名写错或本机没拉取该模型。用 `ollama list` 核对名称后按原样填写
  （含标签，如 `qwen3.5:9b`）。

> 设计口径：HTTP 非 2xx 时，工具会把服务端响应体里的原因**折叠成一行并截断到 300 字**后展示，
> 而不是只给一句「请检查模型名与参数」——后者无法自助定位。

**5）用 DeepSeek 这类云端服务时，先把模型名核对清楚**

「设置」页的模型名必须与**服务端真实模型名**一致，Base URL 填 `https://api.deepseek.com/v1`。

实测（2026-09-21，本机真 key 打 `GET /v1/models`）服务端只列**两个**模型：

```
deepseek-flash        ← 快、便宜（本工具的真 key 探针默认用它）
deepseek-v4-pro       ← 更强
```

两个容易踩的点：

- **`deepseek-flash` 是官方真实模型名**（早期文档里常见的是 `deepseek-chat` / `deepseek-reasoner`）。
- `deepseek-chat` / `deepseek-reasoner` 目前仍被服务端**当别名接受**（请求会成功，返回体 `model` 回显成
  `deepseek-flash`），但它们**不在清单里**，属于随时可能失效的写法。想稳定，就用清单里的名字。
- 若确实写了服务端不认识的名字，会得到 `HTTP 400`（气泡下方的「服务端原文」会说明原因），
  并且**当时不会发起任何消耗**。

不确定就先跑下面这条探针的第 ① 步，它会把**你这份 key 能用的模型名**原样列出来。

想自己确认，可以直接跑仓库里的这个**真 key 探针**（P9 起同时覆盖「数据问答」与「一键全面诊断」两个入口）——它**只读 key，不写任何文件、不落日志**：

```powershell
# 方式一：环境变量（只在当前会话有效）
$env:DEEPSEEK_API_KEY = 'sk-你的key'
node .probe/p9-real-llm.mjs

# 方式二：免环境变量（推荐）——把 key 写进仓库根目录的 .secrets/deepseek.key
#（该目录已在 .gitignore 中，不会进版本库）
node .probe/p9-real-llm.mjs

# 方式三：写进 Windows 用户变量（持久化；探针会直接读注册表 HKCU\Environment，
# 所以刚 setx 完**不用重启终端**也能被读到）
setx DEEPSEEK_API_KEY "sk-你的key"
node .probe/p9-real-llm.mjs
```

> ⚠️ 这三处**只对探针有效**：浏览器页面读不到 Windows 环境变量，应用里的 key 必须在
> 「设置」页的「API Key」里填（只存本机 localStorage）。想让**应用**也连上 DeepSeek，
> 别忘了这一步 —— 光加系统环境变量，界面依旧是离线/未配置状态。
>
> 另注：在「环境变量」对话框里新建变量后**必须点「确定」**才写入注册表。只点「取消」或直接关窗口，
> 列表里看着有、实际没保存（本机实测踩过）。探针在找不到 key 时会自己判断属于哪一种并打印出来。

它会依次做四件事：① 列出服务端**真实可用**的模型名（与你填的对照，不一致会明确告警）；
② 预检一次 `chat/completions`（「关闭模型思考」开 / 关各打一次，把服务端原文打出来）；
③ 真机跑「导入 → 侧栏进 AI 助手 → 问第几子组触发哪条判异规则」，断言回复点名了**子组编号**与
**判异规则 id**、且**没有**再出现「摘要未提供 / 数据不足」这类推诿话术；
④ 真机点一次「**一键全面诊断**」，断言五节齐全（总体结论 / 过程能力盘点 / 主要问题与疑似根因 /
改善行动 / 数据局限与风险提示）、正文超过 400 字、无推诿话术，并确认报告**已持久化**（刷新后还在）。

它能分清两件最容易混淆的事：探针走 `--no-proxy-server` **直连**（绕开 VPN / 代理）。
因此「探针绿、界面仍报连接被切断」指向你的 **VPN / 代理**这一层，而不是 DeepSeek 或本工具。

没配 key 时它会打印用法并以退出码 2 跳过，不会误判成失败。

**6）提示「AI 返回内容读取失败：…被切断」怎么办**

P9 起这句话**不再是一句笼统的「响应流中断」**（旧文案已删除），而是按**证据**分三种说清楚：

- `…连接在返回正文前被切断（未收到任何数据）` —— 收到了 **0 字节**。连接在正文开始前就断了。
- `…响应传到一半被切断（已收到 N 字节）` —— 收到了 N 字节才断。**VPN / 代理在长响应上超时、
  或网关限速**是典型症状（用户实测的两次失败正是这个形态）。
- `等待响应正文超时，连接已中断` —— 服务端在这段时间里一直没把正文发完。若是云端长回答，可到
  「设置」页调小「最大输出 tokens」缩短回答长度，或改用更快的模型后重试。

三种都附了**下一步动作**（`直接再问一次通常即可`），因为这类断流绝大多数是「抽一下就好」。

工具自己会替你做两件事（P9）：

- **瞬时故障自动重试一次**：连接被切断 / fetch 抛错时应用会重发一轮，并在气泡里写明
  `已自动重试 1 次：…`。**超时、你点了「停止」、以及任何 4xx 都不会重试**（重发无意义或有害）。
- **超时预算自适应**：`30s + 最大输出 tokens × 30ms`，上限 120s（探测类固定 3s）。
  旧版固定 30s，会把「模型正在好好写 4000 字报告」误判成故障。

等待期间气泡上方显示 **`AI 思考中…已等待 N 秒`** 与一个**「停止」**按钮：看得见在动，也停得下来
（点「停止」后气泡显示「请求已取消。」，且**不会**触发自动重试）。

想分清是链路还是服务端：跑上一节的 `p9-real-llm.mjs`（它**直连**、绕开代理）。
探针绿而界面红 → 查你的 VPN / 代理（本机实测系统代理开在 `127.0.0.1:7890` 时，长响应会被切断）。

**一键启动命令（Windows `cmd`，可直接复制）**

```
set OLLAMA_ORIGINS=* && set OLLAMA_CONTEXT_LENGTH=16384 && ollama serve
```

改环境变量后需**重启 Ollama** 才生效；随后到「设置」页点「连通性测试」确认已进入 AI 模式。

## AI 助手：对话窗口是「微信式」的

进入「AI 助手」页时，视窗**默认停在最底部**（最新一条消息）；**历史消息往上滚**查看。

- **上拉读历史时不会被拽回底部**：只有当你本来就贴着底部（距底 ≤48px）时，新消息才会自动跟随；
  一旦上拉离开，视窗就停在原处，直到你自己滚回底部附近才恢复跟随 —— 与微信一致。
- **只保留对话**：页面主体就是这段对话。快捷指令、数据主权开关、AI 全面诊断报告都收在
  输入栏左侧的「+」面板里（默认收起），需要时点一下展开；报告已保存时顶栏会出现
  「诊断报告（已保存）」入口直达。
- **对话可以复制**：每条消息（包括你自己提的问题）右下都有「复制」；顶栏「复制对话」把整段
  会话按「我：…／AI 助手：…」拼成纯文本，可直接粘到聊天窗口或邮件里。
- 输入框里**回车即发送**，与「提问」按钮等价。

> 会话记录跨页面切换保留（切到别的页再回来还在），但**刷新页面即清空** ——
> 这是刻意的：对话正文可能含统计结论与你的提问，不落盘以缩小本机留存面。

## AI 回答里的「摘要未提供 / 数据不足」为什么没有了

早期版本只把「能力指数」发给模型，于是你问「第几子组触发了哪条判异规则」时，模型只能
诚实回一句「这份统计摘要里未给出控制图点子序列，因此不能编造……」。**这不是模型不行，
是应用没把数据发出去**。现在每次提问发送的是**已算好的完整上下文**：

| 数据面 | 内容 |
|--------|------|
| 每特性能力 | n / 均值 / σ_within / σ_overall / Ca / Cp / Cpk / Pp / Ppk / 双西格玛水平 / PPM |
| 每特性控制图 | 图型、子组容量与子组个数、CL/UCL/LCL（含副图限）、**逐子组均值与极差序列** |
| 判异明细 | 规则 id 与名称、**涉及的子组编号（1-based）**、说明、严重度；另有逐条超限点 |
| 项目级 | 数据口径、子组配置、启用的判异规则清单、缺陷 Pareto、**可用图表目录**、数据局限 |

提示词里另加了一段**公共数据契约**，硬约束模型：① 只能引用 JSON 里的数值，**禁止臆造**；
② **禁止**写「摘要未提供 / 数据不足 / 无法判断」；③ 必须落到具体对象（点名特性、子组编号、
规则 id）；④ 需要图形佐证时按约定格式引用（见下一节）；⑤ 输出中文 Markdown。

数据主权边界**没有放宽**：子组均值 / 极差是**聚合量**，逐条原始测量值仍然只在「设置」页
勾选「允许发送原始数据」并二次确认后才发送。每次请求实际发了哪些字段，以气泡上的
「发送字段」清单为准（它由构造请求的同一份白名单直接产出，不是另写的一份说明）。

> 序列上限：单特性最多 60 个子组点、全部特性合计 600 点，超出时给「前 30 + 后 30」并在
> JSON 里标 `pointsTruncated: true`。数据局限（截断、被排除的异常值、子组容量不足等）会
> 如实写进 `caveats`，模型被要求据此说明风险，而不是假装数据齐全。

## AI 回复里的图表，是按你自己的数据现算出来的

模型**不画图**，它只在正文里单独一行写一个引用标记，例如：

```
[[chart:control:外壳长度]]
```

前端拿到这个 id 后，用**当前项目你自己的数据**现算并渲染成真的控制图 / 直方图 / 柏拉图
（与「控制图」「能力分析」「柏拉图」页同一套组件与同一套算法），正文里不会露出这串标记。
所以图上的点子、控制限、越限高亮与表格完全一致 —— **不是模型生成的图片**，不会画错数据。

- 可引用的 id 形如 `chart:control:<特性名>` / `chart:histogram:<特性名>` / `chart:pareto:all`；
  清单每次请求都放在 `chartCatalogue` 字段里，模型照着挑。
- **算不出就不画**：id 对应的数据不存在（特性名对不上、样本不足等）时宁可不显示，也不画空图。
- 「复制」单条消息与「复制对话」都会自动去掉这串标记，粘出去的是纯文本。
