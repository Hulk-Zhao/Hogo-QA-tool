# Hogo-QA-tool — 范围决策与行业调研结论

> 本文档由主理人齐活林维护，作为 PRD / 架构设计 / 开发 / 测试各阶段的共同输入基线。
> 后续成员如有异议，须先与主理人对齐，不得各自解读。

## 1. 项目定位

**Hogo-QA-tool** —— 面向制造业质量从业者的 Web 质量管理工具，双模式交付：

- **离线版**：数据不出浏览器，零 IT 基建，打开就用
- **AI 版**：OpenAI 兼容 API 驱动的质量分析助手

核心目标：**把质量人从「整理数据、切换工具、拼凑报告」里解放出来**，把时间还给分析与改善。

## 2. 已确认决策（用户拍板，不可推翻）

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 离线/AI 形态 | 一个代码库两档模式。启动探测 AI 可用性，可用则解锁 AI 助手，不可用自动降级纯离线版，用户无感 |
| 2 | AI 接入方式 | OpenAI 兼容 API（设置里填 Base URL + API Key，兼容 DeepSeek / 通义 / OpenAI / 本地 Ollama）。不配 Key = 纯离线版 |
| 3 | 功能范围 | 用户原选「SPC+MSA+FMEA+8D+报表」完整版，主理人**已砍为两期** |

### 关于决策 3 的削范围理由（记录在案）

MSA 的 ANOVA 方差分量分析、FMEA 的 AIAG-VDA AP 评级表编辑器、8D 的八阶段工作流引擎 —— 这三者**各自的复杂度都不低于整个 SPC 统计内核**。

硬塞进首期的结果必然是每个模块都半成品。而**半成品的质量工具比没有工具更危险**：算错的 Cpk 会让产线做出错误的调整决策，损失是实打实的。

因此：首期把统计内核做对做透，二期再补流程类模块。

## 3. 技术基线

**旧版 Python 工具已确认的能力与缺陷**

| 项 | 现状 |
|---|---|
| 形态 | Python 3.10+ / pandas / matplotlib / openpyxl，PyInstaller 打包 exe，拖拽 Excel 运行 |
| 能力 | 批量 CPK（Cp/Cpk/Pp/Ppk/Ca/西格玛水平）+ 不良柏拉图（300dpi PNG）+ 品质日报 Excel（4 sheet） |
| 输入格式 | xlsx，必须含 `dimension`（物料名称/测量值/USL/LSL）与 `defect`（不良类型/不良数量）两个 sheet |
| **技术缺陷 1** | `std_sub = std_total`，未做子组分组 → **Pp 恒等于 Cp**，Cp/Cpk 与 Pp/Ppk 无法区分。这是统计学上的实质性错误 |
| **技术缺陷 2** | 无控制图、无判异准则、无正态性检验、无 MSA，距离工业界 SPC 基线能力差距很大 |
| 技术缺陷 3 | 无异常值处理流程，异常值直接参与计算 |
| 技术缺陷 4 | 桌面单机，无多用户、无项目库、无审计追溯 |

**旧工具示例数据（已解析确认，可用于验证）**

- `dimension`：3 个物料（外壳长度 / 转轴直径 / 安装孔径），各 50 条测量值，共 150 行；USL/LSL 随行重复
- `defect`：6 类不良 —— 划伤 320、尺寸超差 215、毛边 148、色差 92、变形 45、异物 18

**新版技术栈（主理人建议，架构师可优化但需说明理由）**

- 前端：Vite + React + TypeScript + MUI + Tailwind CSS
- 离线持久化：IndexedDB（项目库）+ File System Access API（导入导出），降级用 Blob 下载
- 统计内核：独立纯函数模块，**不依赖 UI**，便于单元测试与正确性验证
- 图表：轻量自绘 SVG 或 ECharts，需支持控制限/分区带/判异点高亮
- 无后端依赖（离线优先）；AI 调用直连用户配置的 OpenAI 兼容端点

## 4. 首期范围（P0 必须完成）

### 4.1 统计内核 —— 产品的地基

- 过程能力：Cp / Cpk / Pp / Ppk / Ca / 西格玛水平 / PPM 预估
- **区分组内标准差与整体标准差**（修正旧工具缺陷 1）
- 控制图：Xbar-R、Xbar-S、I-MR、P、NP、C、U
- 控制限常数按子组容量自动选取：A2 / A3 / D3 / D4 / B3 / B4 / d2 / E2
- 判异准则：西方电气 4 条 + 尼尔森 8 条，图上高亮 + 违规明细 + 逐条开关
- 直方图 + 规格线 + 正态性检验（Anderson-Darling / Shapiro-Wilk）
- 数据预处理：空值剔除、异常值识别（**只标记不自动删**，须人工确认）、子组划分

### 4.2 分析产出

- 交互式不良柏拉图（保留旧工具能力，Web 化）
- 一键质量日报导出（Excel + 打印/PDF 样式）

### 4.3 双模式

- 离线版：本地项目库 + JSON 项目包导入导出
- AI 版：读数据 → 解读控制图异常 → 给改善建议 → 辅助生成报告文字

### 4.4 数据导入

- **必须兼容旧工具 xlsx 格式**（`dimension` / `defect` 两个 sheet），保证已有数据可迁移
- 支持 CSV / 剪贴板粘贴导入

## 5. 二期范围（本期明确不做）

MSA 量具 R&R（ANOVA + 均值极差法、%GRR、NDC）／ FMEA（AIAG-VDA、AP 评级）／ 8D 报告工作流 ／ SPC 实时监控与告警 ／ MES 系统对接

## 6. 行业调研结论（用于定位与需求取舍）

### 6.1 主流竞品能力与短板

| 产品 | 定位 | 优势 | 短板 |
|---|---|---|---|
| Minitab | 统计深度王者 | 能力分析/DOE/回归无出其右，六西格玛教学标准 | 不实时、需手工导数据、£199+/用户/月、对非统计人员陡峭 |
| InfinityQS Enact | 多工厂企业级 | 统一统计引擎、多厂聚合、合规（21 CFR Part 11） | £200+/用户/月、实施 2-6 周、单厂用属杀鸡用牛刀 |
| WinSPC | 本地部署 | 25 年验证、量具/PLC 直采、无网依赖 | Windows only、界面陈旧、£5000-25000 一次性 + 15-20% 年维护 |
| Ellistat | 欧洲 SPC | 量具连接、报告模板定制、On-Prem/Cloud 双选 | 实施依赖项目支持（3-5 天） |
| NEXSPC（国产） | 纯 Web 私有化 | 1 天上线、终身授权、11 语言、MQTT/OPC 接入 | 偏企业级，轻量个人使用偏重 |
| SPC Dashboard | 云端轻量 | 5 分钟上手、£49/月、Western Electric + Nelson 内置 | 仅云端、无 DOE、公司年轻 |

**能力基线（不做到就不算合格）**：7+ 种控制图、Cp/Cpk/Pp/Ppk、Western Electric + Nelson 判异规则自动识别、能力分析、报表导出。

### 6.2 质量人的真实痛点（产品价值锚点）

1. **Excel 算 CPK 算到眼瞎** —— 复制粘贴半天，异常值没筛干净，Cpk 直接翻车，会上被问「数据靠谱吗」当场社死
2. **高价软件不敢用，杂牌工具功能残缺** —— 进口软件年费肉疼、新人上手要专人带半个月；航发/重工/军工类企业**不敢把生产数据传到云端**
3. **图表一大堆，看完像看天书** —— 图和数字堆满屏，波动原因靠瞎猜；工艺师傅问「这图说明啥、该调哪台设备」，答不上来
4. **数据四分五裂，干活全靠导表** —— MES、计量台账、线下检验单各玩各的，做一次全流程分析要开四五个表格来回复制，整理完已过下班点
5. **内审临时要资料，熬夜拼报告** —— IATF/ISO 审核一来，SPC/MSA/FMEA 资料东拼西凑，预警记录和 8D 问题单对不上，追溯链断一片
6. **报告表演吃掉有效工时** —— 8D 报告格式调整、无关证据收集、精美图表制作，消耗约 35% 有效工作时间，而问题根源往往在第三页就分析完了

### 6.3 由此得出的差异化定位

| 差异化点 | 对应痛点 | 产品动作 |
|---|---|---|
| **轻量** | ② 门槛高 | 浏览器打开就用，无需 IT 基建、无需培训半个月 |
| **数据主权** | ② 不敢上传 | 离线版数据 100% 不出本机；生产数据敏感场景可直接用 |
| **统计做对** | ① 算错翻车 | 修正组内/整体标准差区分；判异准则自动识别替代肉眼；异常值须人工确认 |
| **说人话** | ③ 看不懂图 | AI 把统计结果翻译成「哪条准则触发、可能指向哪台设备/哪道工序」 |
| **一站式** | ④ 来回导表 | 导入 → 分析 → 出报告一条链，不切工具 |
| **审计留痕** | ⑤ 追溯链断 | 每次分析配置与结论可存为项目包，可复现、可导出 |

> 痛点 ⑥（8D 报告）属二期范围，首期通过「日报一键导出」先解决报告拼凑问题。

## 7. 给后续阶段的硬约束

1. **统计正确性是底线**：所有公式必须有明确出处口径，且必须有单元测试覆盖边界（零标准差、单样本、空值、均值偏移、非正态）
2. **统计内核与 UI 解耦**：纯函数模块，可在 Node 环境直接跑测试
3. **离线可用是硬指标**：断网状态下必须能完成导入 → 分析 → 出报告全流程
4. **兼容旧数据**：旧工具 xlsx 必须能直接导入，不得要求用户改格式
5. **判异准则不得简化**：西方电气 4 条 + 尼尔森 8 条必须完整实现，这是与「Excel 手工算」拉开差距的核心
