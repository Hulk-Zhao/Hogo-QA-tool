### 6.4 方法教训（重要）

「PDF 里 `/Subtype /Image` 计数」是**坏代理**：空画布（只有坐标轴）也会被 Chrome 光栅化成位图对象。

**正确做法：把 PDF 渲染成 PNG，再用 vision skill 逐页看图。** 本项目铁律应补一条：

> 涉及图形的产物，必须**渲染出来看**，不能用字节模式计数代替视觉核验。

`diag-charts.mjs`（屏幕 / print 媒体 / PDF 三态对比）、`diag-pareto.mjs`（逐图裁剪截图 + 与独立页对照）、
`diag-stale.mjs`（离线包 `file://` 场景复现）、`diag-resize.mjs`（resize 期间画布是否变空）、
`pdf-inspect*.py`（PDF 逐页位图尺寸 / 文字 / 渲染成 PNG）。

`p0-verify.mjs` 增加**自包含**判据 `chartColorInk`：统计画布中强饱和像素数（数据系列是蓝柱/红线；

> 附带发现：该判据若在图表刚挂载时立即测量，会读到动画首帧（实测 `[581, 402, 0]`）。
> `animation: false` 之后已稳定，脚本中另加 1.2s 兜底等待。

### 10.2 P2-A 规格限自动预填（本轮最重要的用户缺陷）

**现象**（真浏览器复现，脚本 `.probe/p2-repro-spec.mjs`）：导入带 USL/LSL 的 CSV 后，

- 能力页 USL/LSL 输入框**为空**、Cp/Cpk 全显示 `N/A`，并提示「仅提供单侧规格，Cp / Pp 不可计算」；
- **同一份数据**在报表页 Cpk=3.6521（真实值，见 10.8）。

**根因**：`analysisStore.spec` 是独立的编辑态，**从未**与 `characteristic.specLimits` 同步。
报表走 `characteristic.specLimits`（导入值），能力页走 `spec`（初始全 null）→ 同一份数据两个口径。

**改动**：

- `src/store/analysisStore.ts`：新增 `specOverridden: boolean`（默认 `false` = 跟随特性）；
  `setSpec` 改为**同时置 `specOverridden: true`**（用户意图优先）；新增 `applyCharacteristicSpec(limits)`。
- `src/ui/pages/CapabilityPage.tsx`：`useEffect` 预填 + 来源提示 `spec-source-hint`
  （「规格限：来自导入数据（外壳长度）」/「规格限：已手动修改」）+ 恢复按钮 `reset-spec-from-characteristic`。
- `src/ui/pages/ReportPage.tsx`：能力页编辑态不再串台报表（`effectiveSpec`）。

**为什么不是「页面自己读一次 store 就行」**：预填必须是**单向**的——用户一旦手改，
任何自动预填都不得覆盖，否则用户改的值会在下一次 effect 触发时被静默抹掉。
`specOverridden` 就是这条规则的显式载体（也因此它有自己的变异用例 M4/M5/M6）。

### 10.3 P2-B `Math.max(...)` 残留消除

`src/core/math/matrix.ts` 新增 `maxOf` / `minOf`（O(n) 循环；空数组抛 `RangeError`，与 `average`/`range` 契约一致），
`src/core/index.ts` 导出。替换 5 处调用：`charts/xbarS`、`charts/xbarR`、`stats/capability`、`charts/attributes`（2 处）。

**唯一理由（可证伪）**：`Math.max(...xs)` 把每个元素当**实参**压栈，12 万级数组直接
`RangeError: Maximum call stack size exceeded`（`csvImporter` 已在 12 万行真实数据上踩过）。
`src/core/__tests__/maxOf.spec.ts` 用 20 万元素做实测量，并**反向断言**旧写法必抛错——
若哪天这条反向对照不成立，用例自己会红，证明该用例已失效。

`rg -n "Math\.(max|min)\(\.\.\." src --glob "!*.spec.*"` 现仅剩注释与文档文字。

### 10.4 P2-C 全角列名识别

`columnAliases.ts` 的注释一直写着「规范化（去空白、**全角转半角**、转小写）」，但实现只把 `\u3000` 换成空格，
`U+FF01–U+FF5E → ASCII` 从未实现 → 现场用中文输入法粘贴的表头 `ＵＳＬ`/`ＬＳＬ` 一律识别不出，
用户被迫改列名（与 PRD P0-15「避免要求用户改列名」的初衷相悖）。

**改动**：新增导出 `toHalfWidthAscii(s)`（`U+FF01–U+FF5E` 减 `0xFEE0`；`U+3000` → 空格），
`normalizeColumnName` 先调它再压缩空白 / 转小写。

**诚实记录一处口径变更**：独立 QA 用例 `src/data/__tests__/qa_data_independent.spec.ts` 里有一条
「【现状核查】…实现仅转全角空格」的用例，它**断言的是旧的缺陷行为**。本轮修好之后该用例必然失败——
已把它改写成回归防护（断言全角表头被正确映射），并在注释里保留历史。**这是修好缺陷的正常代价，不是「改测试凑绿」。**

### 10.5 P2-D 多特性 Cpk 汇总对比表 + 判定口径唯一真源

### 10.6 验收中发现并修掉的自身缺陷（P2-E）

**现象**：真实浏览器里批量对比表的每一行 DOM 只有 **3 个 `<td>`**（特性 / n / 判定），
Cpk 与 Ppk 的数值是**裸挂在 `<tr>` 下的 `<span>`**。

**根因**：`NumberCell` 组件渲染的是 `<Typography component="span">`，**不是 `<TableCell>`**；
我在批量表里直接把它当成单元格用，漏了外面的 `<TableCell>`。

**为什么必须修**：视觉上它「看起来是对的」——CSS 表格修复规则会把 `tr` 的非单元格子元素包成**匿名表格单元格**，
所以截图与肉眼都正常（vision 复核第一遍也判定「无明显错位」）。
但 DOM 语义、列对齐、可访问性（读屏软件的行列关联）都不可靠——**截图是一个坏代理**。
真正暴露它的是 DOM 断言（`tr.querySelectorAll('td').length === 5`）。

**处置**：补上 `TableCell` 包裹；`CapabilityBatch.spec.tsx` 增加 td 数量断言；
`.probe/p2-verify.mjs` 增加「批量行是完整 5 列」断言。同类写法在异常值表（第 655 行）**本身就是正确的**，
只有本轮新增的批量表漏了。

### 10.10 遗留与风险（诚实口径）

1. **批量表固定 n=5**：批量对比表与报表同口径（`buildCpkSummary` 固定子组 n=5），
   但能力页主表的子组容量是**用户可调**的。用户把 n 改成 10 时，主表与批量表会不一致——
   卡片文案已写明「子组容量 n=5」，但**更好的做法是让批量表跟随当前子组设置**（下一轮）。
2. **报表页 UI 的 Cpk 表没有「判定」列**：判定文案目前只在 Markdown / Excel 导出里出现，
   页面表格只有 特性/n/Cpk/Ppk/Cp/Pp。批量表已有判定列，报表 UI 未对齐（属既有限制，非本轮引入）。
3. **全角转换只覆盖可见区**：`U+FF01–U+FF5E` 与 `U+3000`；
   不做繁简 / 异体字 / 其他 Unicode 空白（如 `U+00A0`）归一。
4. **`specOverridden` 是会话内状态**：不落盘。刷新后回到「跟随导入规格」，
   用户的手改规格限不会保留（P0-14 的 `setSpec` 语义与持久化范围未变）。
5. 其余遗留同第九节（未保存即刷新仍为空、xlsx CVE 缓解非根治、bundle ~2.1MB、AI 会话内存态等）。
