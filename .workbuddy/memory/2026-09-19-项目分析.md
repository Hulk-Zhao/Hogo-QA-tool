## 二、专家团发言实录

### 1. 产品交付经理 ——「用户要的东西,有三件没送到」

> 对照 PRD 与第五轮需求逐条核验:

1. **【P0】报表「包含图表」勾选项是空转。** `ReportPage.tsx` 全文未 import 任何图表组件,`getDataURL` 全库零命中。打印输出**永远只有表格**——这正是用户第五轮截图反馈「打印预览只有三张表、一张图都没有」的根因。当前 `includeChartImagesInPrint` 只是给 body 加减一个 CSS 类,控制的对象不存在。
2. **【P0】导出范围勾选粒度不达标且不落盘。** PRD P0-18 要求 6 项可勾选(CPK汇总/不良统计/原始尺寸/原始不良/控制图截图/柏拉图截图);现状只有 2 项(图表/表格),且 `ReportPage.tsx:57` 用 `useState` 管理——用户第五轮明确要求「勾选状态走 settingsStore 持久化,不要 useState」。
3. **【P0】「AI 全面诊断」(#12)完全未实施。** 全库 grep `fullDiagnosis` 零命中;`AiAssistantPage.tsx` 快捷指令仍是 5 个旧功能。
4. **P1 需求池缺口**:`P1-02 配置模板`、`P1-03 多特性批量能力分析`(CapabilityPage grep 无批量/排序)、`P1-05 报表模板`、`P1-06 趋势对比` 均未启动;`P1-01 Markdown 导出`、`P1-04 项目库` 已完成。

### 2. 统计专家 ——「内核可信,边界清晰」

- 双西格玛口径(σ_within / σ_overall)实现正确,I-MR 降级路径完整(`capability.ts:72-85`)。
- 常数表经 QA 三轮独立验证,c4 截断缺陷已修;判异准则 N5-N8 逐点 σ 已修。
- **遗留提示**:PPM 估算目前只有正态假设分支,PRD §10 待议项 3(非正态 PPM)仍需用户拍板是否进 P2。
- 无新增统计缺陷。

### 3. 架构师 ——「分层干净,但项目没有救生衣」

- `core → data → services → ui` 边界由 ESLint `no-restricted-imports` 强制,零违规;存储走窄接口注入,Node 可测。
- **【P1】项目无 git 版本控制**(实测 `git rev-parse` 报 not a git repository)。第三轮已发生过「根目录 12 个配置文件集体消失」事故,当时靠 `node_modules/.package-lock.json` 反推重建——没有 git,下一次事故可能无法恢复。**这是当前性价比最高的一件事:一条 `git init` 即可消除。**
- **【P1】README 功能矩阵失真**:AI 助手/设置/项目库仍标 🚧,实际第三轮已接线可用。文档失真会误导后续开发决策。

### 4. QA 专家 ——「734 绿灯,但有 4 个用户可见缺口没被任何测试看住」

- 测试数 530→734,四门禁真实有效(非空洞)。
- **方法论缺口**:报表图表、判异开关持久化这类「接线类缺陷」正是本项目反复踩的坑(已累计 5+ 次)。每个新接线点都必须配「注入假协作者 + 变异测试证明可证伪」的用例——#11/#12 的测试目前不存在,所以缺口能活着到达用户手里。
- 建议:#11/#12 修复时同步补变异测试(破坏实现必须变红)。

### 5. 前端性能专家 ——「能用,但在变胖」

- **【P2】单文件 bundle 2.13 MB**(echarts + xlsx + MUI 全量内联)。`file://` 双击场景无法 code-split(单文件约束),但 `dist-server` 版可配 `manualChunks` 把 echarts/xlsx 拆为懒加载,改善 HTTP 形态首屏。
- **【P2】`Math.max(...arr)` 残留 4 处**(`xbarS.ts:24`、`xbarR.ts:42`、`attributes.ts:77/207`、`capability.ts:88`)。csvImporter 的同类问题已修(12 万行 RangeError),这 4 处操作数是子组数(量级小),**风险低但口径不一致**,建议统一为 O(n) 循环消除隐患类别。
- 大数据分页/虚拟滚动:DataTable 当前全量渲染,20 万上限数据在原始数据页可能卡顿(未实测,列为观察项)。

### 6. 安全与数据主权专家 ——「两条供应链/凭据风险」

- **【P1】`xlsx@0.18.5` 存在已知 CVE**(原型污染 CVE-2023-30533 等,SheetJS 官方已不在 npm 维护修复版)。导入器无 `__proto__` 键防护。建议:评估迁移 `exceljs` 或 SheetJS CE 最新版;短期可在 `xlsxImporter` 出口处做 key 白名单过滤。
- **【P1】API Key 明文存 localStorage**(file:// 下唯一可用后端,已在设置页加提示)。属已知权衡,建议补一条「一键清除配置」入口的回归测试,并在 README 风险节固化说明。
- 数据主权本体健康:payload 白名单拷贝 + AiUsageLog 审计 + 二次确认,均在位。

### 7. UX 与文档专家 ——「一致性欠账」

- **【P0】判异准则开关刷新即重置**:`ControlChartPage.tsx:77` 与 `SettingsPage.tsx:103` 双处 `useState`,未进 settingsStore、未持久化。用户改完开关刷新就丢,属于「设置不可信」级别的体验缺陷(第四轮已识别,至今未修)。
- 导入页/柏拉图页的 `useState`(tab、阈值)属页面临时态,合理,无需动。
- README 与实现脱节(同架构师第 3 条)。
